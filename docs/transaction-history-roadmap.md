# 首页快捷入口与交易历史开发方案

## 目标

在不改变 RN 既有快捷操作语义和链上规则的前提下：

1. 将首页“买币”从首页五项快捷操作中移入“更多”底部抽屉。
2. 在“更多”抽屉增加“交易历史”入口。
3. 新增账户链上历史页面，查询当前登录账户的 `history_api` 记录。
4. 参考 RN 的深色移动页面节奏，并吸收提供的参考图交互：日期分组、类型筛选、正负资产变化、可展开的详情页。

## 范围与边界

- 仅展示当前登录账户的链上记录，不增加管理员、邀请、签到或第三方 DApp 聚合能力。
- 数据源使用当前已连接的 Graphene 节点 `history_api`，不使用本地缓存伪造记录。
- 首批支持通用账户操作：转账、成交、创建/取消限价单、账户/资产/权限更新、流动性池和闪兑等；未识别操作显示“链上操作 #类型”，原始 ID 仍可展开查看。
- 账户历史为只读页面，详情展示原始链上字段的脱敏/截断版本；不保存私钥、不新增签名流程。

## 分阶段开发

### 阶段 1：入口与路由

- [x] 首页快捷操作移除“买币”，保留转账、收款、闪兑、更多。
- [x] “更多”底部抽屉增加“交易历史”图标入口。
- [x] 增加受保护路由 `/history`，未登录时回到登录页。

### 阶段 2：链上数据契约

- [x] 在共享 core 增加账户历史的结构化类型。
- [x] 封装 `get_account_history_by_operations`，保留历史 ID、时间、操作类型、操作内容、结果、区块位置。
- [x] 解析常见操作的展示标题和资产变动；金额严格按链上资产精度换算。
- [x] 节点接口异常、空记录、分页边界均提供可见状态。

### 阶段 3：历史列表页

- [x] 顶部返回栏、标题“交易历史”、刷新入口。
- [x] 类型筛选底部抽屉：全部、转账、成交、订单、流动性、其他。
- [x] 按本地日期分组。
- [x] 列表项展示操作图标、标题、来源/对手方、正负资产变化。
- [x] 支持加载中、空状态、失败重试和按钮刷新。

### 阶段 4：详情与验收

- [x] 列表项点击打开 `/history/:id` 详情页。
- [x] 展示支付/接收资产、时间、操作类型、区块高度、交易/操作位置、历史 ID 和链上操作。
- [x] 长字段在详情中自动换行，避免破坏窄屏布局。
- [ ] 使用真实登录账户验证转账、成交和未知操作三类记录。
- [x] 增加统一可读化解析：转账、限价单创建/取消、订单成交、借贷仓位更新、治理提案、喂价和流动性操作均输出中文交易描述；列表和详情共用解析结果。
- [x] 完成 Web 类型检查和生产构建；移动窄屏视觉仍需浏览器人工复核。

## 验收标准

- 首页“买币”只存在于“更多”抽屉，不再占用首页快捷操作位置。
- “更多”抽屉能直接进入交易历史，入口关闭后状态不残留。
- 登录账户打开 `/history` 可看到真实链上记录；无记录时显示明确空状态。
- 交易记录的正负颜色、日期分组、详情字段与参考图的阅读层级一致。
- 不能因为单条未知操作解析失败而阻塞整个列表。
