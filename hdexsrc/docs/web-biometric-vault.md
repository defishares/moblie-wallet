# Web 本地私钥保险箱

## 目标

Web 端不把账户密码、私钥 WIF 或助记词发送到业务后端。首次账户密码登录成功后，用户可以注册本机 Passkey；浏览器通过 WebAuthn PRF 输出派生 AES-GCM 密钥，将 WIF 加密后保存到 IndexedDB。后续登录可使用设备验证解锁，账户密码仍然是恢复方式。

## 已实现流程

1. 账户密码登录按 RN 规则从 `账户名 + active + 密码` 派生 WIF，并通过链上权限校验。
2. 首次登录展示“启用设备验证”提示。用户确认后调用 `navigator.credentials.create()`，要求平台设备验证和 `prf.eval`。
3. PRF 输出经 HKDF-SHA-256 派生 AES-256-GCM 密钥；WIF 只以密文、随机 salt、随机 iv 写入 IndexedDB。
4. 应用启动或刷新时先查找本设备上的保险箱；只有一个账户时自动发起一次设备验证，成功后恢复会话。多个账户时，登录页输入账户名后显示“使用设备验证登录”。`navigator.credentials.get()` 解锁后只把 WIF 放在当前标签页内存中。
5. 设置页可以查看、启用或关闭设备验证。关闭会删除本设备上的加密密文，但不会影响链上账户。
6. 现有会话仍在一小时无操作/页面长时间隐藏后自动清除，退出登录只清除内存会话，不会误删保险箱。

## 边界与降级

- 设备验证需要 HTTPS 或 `localhost`/`127.0.0.1` 安全上下文，并且浏览器/平台验证器支持 WebAuthn PRF；不支持时保留账户密码登录。
- 浏览器不会向页面暴露指纹、面容等生物特征数据；设备可能实际使用生物识别、系统 PIN 或安全密钥，由操作系统决定。
- IndexedDB 中不保存明文 WIF。页面解锁后 WIF 必然短暂存在 JavaScript 内存，因此仍需严格 CSP、避免不可信第三方脚本，并保持短会话生命周期。
- Passkey 的跨设备同步不等于 IndexedDB 密文同步；换设备需要在新设备上用账户密码重新登录并重新注册设备验证。
